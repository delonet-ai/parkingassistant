# Эксплуатация стенда

Короткий runbook для режима «один администратор»: как ввести систему в работу, что проверять
каждый день, как делать резервные копии и восстанавливаться. Всё выполняется на хосте OMV из
чекаута `/opt/git/parkingassistant`. Как устроен деплой — [ADR 005](adr/005-stand-deploy-via-host-checkout.md)
и раздел «Deployment» в [TECHNICAL_README](TECHNICAL_README.md).

## 1. Перед первым запуском в работу

### Env стенда (`staging/env/app.env`)

Шаблон — [`.env.example`](../.env.example). На стенде должно быть:

| Переменная | Значение | Зачем |
|---|---|---|
| `JOBS_SERVICE_TOKEN` | `openssl rand -hex 32` | Без него API закрыт для планировщика: ни один из пяти регламентных job-ов не выполнится (`401`), очередь утром не раздастся. |
| `POSTGRES_BIND` | `127.0.0.1` (по умолчанию) | Postgres не торчит наружу. Стек ходит в БД по внутренней сети compose, бэкапы — через `docker exec`. |
| `POSTGRES_PASSWORD` | не `change-me` и не `parkingassistant` | Если меняете на уже работающем стенде — сначала `ALTER USER parkingassistant PASSWORD '…'` внутри Postgres: каталог данных помнит первый пароль. |
| `API_PORT` / `ADMIN_UI_PORT` | `3330` / `3340` | `ADMIN_WEB_PORT` больше не читается — сервис называется `admin-ui`. |

`JWT_SECRET` и `SESSION_SECRET` никем не читаются ([ADR 007](adr/007-session-based-access-control.md)) —
их можно удалить из файла.

### Первый вход администратора

После деплоя версии с авторизацией админка на `:3340` открывается экраном первой активации:
логин `sysadmin`, пароль задаётся один раз (не короче 10 символов). Активация возможна только
пока в системе нет других учётных записей — сделайте её сразу после деплоя.

Режим одного администратора — это одна учётная запись `system_admin`. Вкладка `Доступ` позволяет
позже добавить `parking_admin` без прав на управление учётками.

### Справочники

- Каталог мест: вкладка `Места` → загрузка `.xlsx` (с предпросмотром).
- Постоянные закрепления: пока только из консоли —
  `docker exec parkingassistant-api npm run db:import:permanent-assignments`
  (читает `staging/imports/parking-catalog.xlsx`, путь меняется `CATALOG_XLSX_PATH`). Отдельные закрепления правятся во вкладке `Справочники`.
- Роль места задаёт, как оно участвует в распределении:
  `rotatable` — гостевой пул (гостю выдаётся первым), `blocked` — место выведено из эксплуатации.

## 2. Как система считает свободные места

Пул дня — это места, которые на эту дату:

- отдал их постоянный владелец, **или**
- ни за кем не закреплены постоянно,

и которые не архивированы и не `blocked`. Из этого пула берут очередь, гости, ручные назначения
и перевод между местами; гостевой резерв `5` считается от него же. Место с владельцем, который
его не отдал, показывается в «Дне» как **«у владельца»** и не выдаётся никому.

## 3. Регламент дня

| Время | Job | Что проверить, если что-то не так |
|---|---|---|
| 07:00 | `lock_departure_plans` | время выезда на сегодня больше не редактируется |
| 08:00 | `process_queue` | очередь на сегодня раздана, вкладка `Заявки` |
| 08:05 | `rebuild_conflicts` | конфликты ранних выездов во вкладке `Линии` |
| 19:00 | `freeze_next_day`, `unlock_employee_pool` | отдачи на завтра заморожены, посчитан пул сотрудников |

Статус каждого запуска — вкладка `Журнал` → jobs. Упавший запуск тоже записывается, с текстом
ошибки. Логи планировщика: `docker logs --tail 100 parkingassistant-jobs`.

## 4. Резервные копии

```bash
/opt/git/parkingassistant/scripts/ops/backup.sh
```

Пишет `staging/backups/<дата-время>/` с `db.dump` (pg_dump), `storage.tar.gz` (подложки этажей
и импортированные каталоги) и `SHA256SUMS`. Дамп сразу проверяется чтением (`pg_restore --list`);
неудачный прогон не оставляет каталога, похожего на бэкап. Хранится `KEEP_DAYS=14` дней.

Ежедневно через crontab хоста (`crontab -e` под root):

```cron
30 3 * * * /opt/git/parkingassistant/scripts/ops/backup.sh >> /opt/git/parkingassistant/staging/logs/backup.log 2>&1
```

`staging/backups` лежит на том же диске, что и база. От отказа диска это не защищает —
копируйте каталог бэкапов на другой носитель (NAS-шара, внешний диск) штатными средствами OMV.

## 5. Восстановление

```bash
/opt/git/parkingassistant/scripts/ops/restore.sh staging/backups/20261112-033000            # только БД
/opt/git/parkingassistant/scripts/ops/restore.sh staging/backups/20261112-033000 --storage  # БД + подложки и импорты
```

Скрипт проверяет контрольные суммы, **сначала делает бэкап текущего состояния**, останавливает
`api`, `admin-ui`, `jobs`, пересоздаёт базу из дампа и поднимает стек обычным `stand.sh` (миграции
применятся заново, если дамп старше схемы). Для подтверждения нужно ввести имя базы.

Проверка после восстановления — `npm run smoke:stand` и вход в админку.

## 6. Проверка после каждого деплоя

```bash
ssh omv /opt/git/parkingassistant/scripts/deploy/stand.sh
npm run smoke:stand
```

Затем в админке: `День` открывается на сегодня, KPI «Доступно к назначению» не ноль, в `Журнале`
последний прогон jobs без ошибок.
